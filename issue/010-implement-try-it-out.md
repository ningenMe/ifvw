# Try it out機能を実装する

関連: #1 (concept), #008

## 背景

OpenAPIの情報を利用して、実際にAPIリクエストを送信できるようにする(Swagger UIの「Try it out」相当)。

このプロダクトは常駐サーバーを持たず、CLIが生成した静的サイト(`011-generate-static-site`)として配布される方針にした。
そのためTry it outはブラウザから対象サービスへ直接リクエストするしかなく、対象APIがCORSを許可していないと動かない。
サーバー側proxyという回避策は今の方針(静的サイト)とは相性が悪いため、実現方法は保留中。着手前に方針を決める。

## やること

- (方針決定)静的サイトのままでCORS制約を受け入れるか、別途proxy用の軽量ランタイムを用意するかを決める
- API詳細画面にリクエストパラメータ/request bodyの入力フォームを追加する
- 入力内容から実際のHTTPリクエストを組み立て、対象サービスへ送信する
- レスポンス(status code / headers / body)を表示する
- CORSで送信できない場合のエラー表示・案内を用意する

## 完了条件

- 実際のAPIエンドポイントに対してリクエストを送信し、レスポンスを画面上で確認できる(対象がCORSを許可している場合)
- CORSで送信できないケースでは、その旨が分かるエラー表示がされる
